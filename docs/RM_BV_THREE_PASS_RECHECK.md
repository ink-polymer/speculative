# RM-BV 三轮反向核查

日期：2026-09-07。范围：现有实现、理论主张、公开最近邻和正式实验入口。
本轮只新增审计测试与文档，未改推理实现，未连接 GPU，也未产生性能结果。

## 结论先行

当前版本不能冻结为“已验证原创、顶会级、快于 DDTree”的最终主方法。
这不是因为已有组件不能组合创新，而是本轮找到了**多步收益失效的明确反例**，
且通用框架级新颖性和 RM 专属正式实验流程仍未通过。

| 检查项 | 本轮结果 | 允许的结论 |
| --- | --- | --- |
| 合法输入下的概率律 | 独立有理数流枚举与实际分类抽样分支枚举一致 | 加强现有实数无偏性论证；不是浮点绝对精确证书 |
| 多步相对收益 | 找到 RM-BV 输给同树 early-root BV 的反例，正概率扰动后仍成立 | 不存在当前规则对 early-root BV 的无条件多步优势 |
| 后缀后再选根集合 | 构造出总变差距离 1/4 的偏差 | 该适配违反前提；当前 propose 未这样做 |
| 原创性 | 后向流归约仍成立；新核对 DominoTree 的条件草稿构树 | 剩余前向构造差异尚未获得原创性确认 |
| 正式实验 | RM 配置可由通用 runner 执行，但正式入口硬编码 TM 方法 | 不能把旧 TM 协议或计划数量记作 RM 完成证据 |

## 第一轮：不复用核心实现公式的分布核验

新增 `tests/gbv_paper/test_root_marginal_adversarial.py`。

独立 oracle 使用 Python `Fraction`：逐层建立根分支的 Target 容量，为每个共享
后缀符号只提供一份 proposal 容量；直接得到 endpoint/root/correction 的联合流，
再用后向失败概率连乘求输出块分布。它不调用生产实现的 `_mixture`、
`_terminal_rows` 或 `block_verify`。

检查包含：

1. 固定 seed 的 24 个有理数 Target/proposal 实例，词表 2/3、后缀长度 0/1/2、
   部分或完整根集合以及零概率。先严格核对 Target 补全后的**完整联合分布**，
   再分别穷举参考版和张量版每一次实际分类抽样，与 oracle 比较，容差 1e-12。
2. 长度 5 的多轮解码 oracle：按已提交上下文改变根集合、proposal 和块长，检查
   最终联合分布；随后检查 EOS 截断。分别覆盖严格正概率与含零概率情况。
   此项是有限分布组合核验，不是实际大模型 CUDA 多轮实验。
3. 下节两个负收益实例，同时以有理数 oracle 和实际张量版/early-root 实现复核。

独立 oracle 的流表达与先前 LV 归约相符；这验证实现对应的概率律，而非证明
原版 LV 的标准前向算法与 RM 完全相同。

### 前提违规的负测试

设 Target 是两个独立均匀二元 token，proposal 后缀 z 也均匀。如果在看到 z 后
再设根集合 S={z}，仍套用当前 gate/BV/后验规则，则最终前两个 token 的分布为：

    P_bad(00)=P_bad(11)=3/8
    P_bad(01)=P_bad(10)=1/8

正确 Target 四种情况均为 1/4，总变差距离为 1/4。
当前 `propose` 先定根后抽后缀，没有这个错误。今后若做自适应选根/剪枝，
不能无证明地改成看到本轮后缀后再选择集合；仅给已有合法 verifier 换一个选择器
也不会自动保留无偏性。

## 第二轮：多步收益反例

根 A 的分布为 (3/5, 2/5)，两个根都包含在树中。共享后缀长度为 2：

    Q(Y1)=(1/4, 3/4), Q(Y2)=(0, 1).
    P(Y1 | A=0)=(3/10, 7/10), P(Y2 | A=0,Y1)=δ1.
    P(Y1 | A=1)=(1, 0),       P(Y2 | A=1,Y1)=δ0.

完整后缀后的 bonus 分布为 P(B | A,Y1,Y2)=(1/2,1/2)。两种方法使用**相同 Target、相同共享
proposal、相同两根三层六节点树分布、相同 BV 规则**；区别仅为是否先选根。
每轮提交长度包含根、接受后缀和一个 correction/bonus token。

| 方法 | 精确期望提交长度 | 小数 |
| --- | --- | --- |
| RM-BV，延迟选根 | 4593/1450 | 3.1675862069 |
| 先选根，再 BV | 81/25 | 3.2400000000 |

差为 21/290，early-root 更高。另一个严格正概率版本把上面每个 (0,1)/(1,0)
分别替换为 (0.01,0.99)/(0.99,0.01)，包括 Q(Y2)，其余不变：

    RM-BV        = 1271561/400000 = 3.1789025
    early-root   = 40613/12500    = 3.24904
    early − RM   = 5611/80000     = 0.0701375.

因此失败不是零概率边界或浮点舍入造成的。局部跨根容量池的最大流结果不能推出
多步期望提交长度对 early-root BV 的支配关系。复制/奇偶族上的正例仍有效，
但只能说明存在收益区域，不能推出普遍收益。

这里比较的是数学提交长度，不是 GPU tokens/s，也不是说实际模型上一定输给
DDTree。端到端是否更快还取决于每轮耗时，必须实测。

## 第三轮：等价关系、最近邻与实验闭环

### 原创性边界

- 条件于 S，RM 可以表达为：对 Target 消去根变量，调用已有 BV，然后按包含
  correction 的条件后验恢复根。这是我们对当前方法的归约，不是某篇论文的原句。
  单靠“换采样顺序”或“后验选根”不能获得通用框架级创新。
- [GBV 的 Lemma 4.4](https://arxiv.org/html/2602.16961v1)允许在其 IID 多路径设定下
  将有效验证器分解成选路与单路径验证；不能只凭选路发生先后断言超出该框架。
  当前相关 proposal 不等于该文具体 IID 构造，因此也不能直接判定完全重复。
- 先前 [LV 核查](RM_BV_NOVELTY_AUDIT.md)的后向行概率归约未被本轮推翻。
  [作者页](https://chulheeyun.github.io/publication/cha2026layer/)确认其为通用层级
  lifting 方法。完整 PDF 访问限制仍在，不能将最近邻全文检查标记完成。
- 新核对 [DominoTree §3.1–3.5](https://arxiv.org/html/2607.08642v1)：它把
  Domino 的路径条件修正用于草稿树打分，验证阶段复用已有树验证。
  它不等于 RM 的 Target 根边际化，但进一步排除了把“并行草稿＋条件性＋树”
  这类宽泛组合单独称作空白的表述。这里没有复核其报告的速度结果。

仍值得研究的部分是共享 proposal 下可高效计算的前向流与树结构联合设计，
但当前固定共享后缀规则没有被证明是已有框架之外的重要新构造，更没有普遍收益。
它属于推理解码算法/执行结构的变化，不是 Target 或 DFlash 网络结构修改。

### 正式实验入口检查

`terminal_protocol.py` 的 `NAMES`/`METHODS`、`variants()` 和 study schema
固定在 TM 六方法；`terminal_formal.py` 的 replay 与单元门槛也按该协议组织。
换成 RM JSON 不能自动得到 RM 正式研究：配置中的十方法不会直接替代这些硬编码。

RM 配置确实保留原七数据集、模型 revision、样本协议与 DDTree/DFlash/机制消融。
但还需要独立 RM study、RM 状态重放（包括真实 Q）、冻结数据与代码指纹、
三次 timing repeats 和对应统计，以及实际 checkpoint/GPU 的正确性检查。
共用引擎的 DDTree/DFlash 对照还不能冒充各官方最快运行栈的完整复现。

本轮不修改正式入口，不启动正式测试集调参，不把审计测试计为性能实验。
