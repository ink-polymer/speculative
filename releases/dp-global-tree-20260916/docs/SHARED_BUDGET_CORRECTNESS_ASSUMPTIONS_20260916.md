# 当前保留版本：共享预算解码的正确性条件与验证范围

验证对象为审计矩阵中的冻结现版本，不是已拒绝的plateau候选。生产源码和默认值不修改。

## 理想精确算术下的条件性论证

1. 对每个请求先从Target的首token分布抽样，建立已生成前缀。
2. 调度仅使用已生成前缀、请求年龄、Draft提案概率及事先校准代价曲线；预算分配不读取本轮尚未抽取的Target token。每个入场请求至少有根节点；延迟入场只是等待，不生成或删除token。
3. 树中每个节点只看该请求的已提交历史和自己的祖先，并使用正确逻辑位置。要求该节点的Target条件分布等于普通自回归Target在同一token前缀上的分布。这个要求在精确算术中来自相同可见上下文，不自动保证GPU有限精度实现逐bit相同。
4. 对各节点独立抽取一个Target posterior token。沿根到出口的路径，每次选择的节点只由此前已观察的路径token决定；尚未访问节点的随机抽样独立。对未访问节点的抽样求和得到1，所以访问路径的概率恰为逐token条件概率之积。
5. 接受树边的token来自对应Target posterior；树外的bonus/correction也是当前路径节点的Target抽样，而不是未验证的Draft token。结束本轮并重建树是基于已观察路径的停止规则。
6. 多轮按条件概率的链式法则组合，得到完整序列分布；共享调度不改变每个请求的条件生成核。若请求的Target随机源独立，其联合序列分布为各请求AR分布之积。
7. 首个EOS即停止；max_new_tokens按已生成token前缀截断。树批次中EOS或长度上限后的未使用抽样被丢弃，不再次输出。末轮KV可能临时保留超过输出截断点的已计算行，但完成请求不会再次查询它；必须保证容量安全且不影响其他请求。

## 必须检查的边界

- 同一父节点重复同一个子token不能形成含糊路径，当前参考验证器拒绝；相同token出现在不同父节点是合法的。
- Tree父节点须在子节点之前，根父节点为-1；不存在合并节点/DAG语义。当前版本不声称处理合并。
- Target每行必须有限、非负且具有正总质量；零概率token不会被抽到。Draft零支持只能降低树覆盖率，不能从Target抽样支持集中删token。
- 每请求KV、位置、特征只更新为自身根和接受路径；其他请求KV不可见，不混入其特征。根的旧token不可重复计为新输出。
- 不使用未来token、未访问posterior样本或事后测评答案选预算。

## 本次执行验证

- 有限状态精确穷举：真实参考验证函数的所有节点抽样，包括未访问节点，按有理数权重积分；多请求入场、预算、年龄权重、多轮、EOS、截断后完整联合分布与AR精确相等。它不是现实模型的全域形式化证明。
- 注入错误测试：故意损坏prefix打包、掩码和KV回写，审计器必须检测；验证审计器不是只复用被测输出自证。
- H20实际历史：两模型、两温度、三预算、五并发；C1四条独立请求，其余固定批次，64token上限。逐轮逐层检查prefix打包和保留、路径KV回写、特征历史、掩码、位置、全局行预算。所有探针前后检查请求RNG不被额外消耗，并与无探针执行比对输出。
- 数值探针：用逐字节相同的实际旧KV进行逐token祖先路径重放；选定请求跨生成阶段建立单query教师强制AR影子KV；T0实际首次分歧与固定单请求因果AR的完整logit向量比对。只序列化误差与摘要，不将探针耗时当作性能。
- T1 GPU固定七节点二叉树采样smoke：检查100000次完整三token输出的频率，不能代替真实模型的完整序列分布认证。

## 结论规则

结构检查和穷举通过，只允许说被测不变量/有限状态规律通过。
只要T0存在逐token不一致，严格等价不能写“通过”；只要真实条件概率与规定AR参考存在数值差异，不能宣称保留该有限精度参考的精确分布。
必须把理想算法论证、GPU结构检查、GPU数值差异及任务准确率分开。任务准确率不在本次解码正确性审计范围内。
